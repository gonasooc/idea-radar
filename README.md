# idea-radar

매일 아침 신규 앱·웹서비스를 한 페이지에서 훑고, 나중에 검색해 다시 찾기 위한 개인용 아카이브.

GitHub public repo 하나로 끝난다. Actions가 매일 새벽 소스들을 긁어 JSON으로 커밋하고, 같은 repo의 GitHub Pages가 그걸 정적 페이지로 보여준다. 서버·DB·도메인·유료 서비스가 없고 운영 비용은 0이다.

## 무엇을 하는 도구인가

아침에 직접 열던 사이트 6곳을 대체한다. 이 목록이 곧 성공 조건이다.

| 소스 | 무엇이 올라오나 | 하루 |
|---|---|---|
| GeekNews Show | 국내 개발자가 만든 것 자랑 | 5~12건 |
| Disquiet | 국내 메이커 제품 등록 | 8~10건 |
| SYDE | 사이드프로젝트 쇼케이스 | 1~2건 |
| 조코헌트 | 한국판 Product Hunt | 2~3건 |
| 일딴 | 바이브코딩 결과물 마켓 (웹·앱·게임) | 1~2건 |
| Product Hunt | 글로벌 신규 제품 | 8~13건 |
| Show HN | 해외 개인 프로젝트 (별도 접힘 영역) | 140~165건 |

Show HN을 뺀 나머지가 하루 25~30건이다. 아침에 훑기 좋은 양이고, Show HN은 물량이 5배라 기본 접힘 + 별도 파일로 격리한다.

**2주 뒤 kill test**: 14일 후에도 위 사이트를 여전히 직접 열고 있으면 이 도구는 실패다. 그때는 기능을 더 넣지 말고 왜 안 열게 되는지부터 본다.

## 빠른 시작

```bash
node --version            # v24 이상 필요 (타입 스트리핑으로 .ts 직접 실행)

node src/run.ts --dry-run          # 파일 안 쓰고 수집만 확인
node src/run.ts --only=disquiet    # 소스 하나만
node src/run.ts --seed             # 최초 1회. 수집분을 '오늘 신규'에 안 띄움

npx serve site                     # 로컬에서 페이지 확인
```

런타임 의존성은 0개다. `package.json`에 dependencies를 추가하지 않는다 (SPEC의 "잘라낸 것" 참조).

## 운영

- 수집: 매일 2회 — **04:37 KST**(`37 19 * * *` UTC, 아침 보기 1시간 반 전) + **12:07 KST**(`7 3 * * *` UTC, 점심 직후 보기용).
- 수동 실행: Actions 탭 → collect → Run workflow.
- 고장 감지 1순위는 이메일이 아니라 **페이지 상단 배너**다. 26시간 넘게 수집이 안 되면 빨간 배너가 뜬다. 파이프라인이 조용히 죽는 경우(스케줄 자동 비활성화, cron 드롭, Pages 미배포)는 Actions가 실패하지 않아 이메일이 오지 않는다.
- 소스 하나가 반나절~하루 실패하는 건 정상 범위다. 연속 실패 중이면서 마지막 성공이 40시간을 넘은 소스가 있어야 job이 빨간불이 된다.

## 설계 원칙

1. **가공하지 않는다.** LLM 요약·분류·키워드 필터 없음. 제목·한줄설명·링크·날짜·출처를 원본 그대로 저장한다. 이전 프로젝트에서 분류 규칙 튜닝이 유지비 폭탄이 됐다.
2. **조용한 실패를 만들지 않는다.** 파싱 0건은 예외를 던진다. 빈 배열을 조용히 반환하는 게 가장 위험한 실패 모드다.
3. **기록된 항목은 불변이다.** 같은 id를 다시 봐도 덮어쓰지 않는다.
4. **소스 하나 = 파일 하나 = 독립적으로 죽을 수 있는 것 하나.** 하나가 깨져도 나머지는 그날 데이터를 남긴다.
