# UI 디자인 기준

UI의 시각적 기준과 상호작용·반응형·접근성 기준을 다룬다. 시스템 구조는 [docs/architecture.md](architecture.md), 기술 스택·구현 도구 설정·검증 명령은 [docs/specs.md](specs.md)에서 관리한다.

합의된 디자인 기준의 정본은 [SPEC.md](../SPEC.md) 6.6이다. 여기서는 그 기준과 현재 코드에서 관찰한 구현을 연결하고, 확인하지 못한 것을 구분해 남긴다.

## 참고할 코드와 화면

- [site/style.css](../site/style.css) — 디자인 토큰(`:root`), 라이트/다크 팔레트, 컴포넌트 스타일 전부.
- [site/index.html](../site/index.html) — 화면 골격. 헤더(브랜드·테마 토글·배너 2종·검색·칩 3줄·건수 줄), 목록, 푸터.
- [site/app.js](../site/app.js) — 렌더 로직. 어떤 상태에서 어떤 컴포넌트가 나오는지는 여기서 정해진다.
- [SPEC.md](../SPEC.md) 6절 — 화면 동작과 색·글자 기준의 정본.
- 배포된 화면: `https://gonasooc.github.io/idea-radar/` ([site/index.html](../site/index.html)의 `og:url`).

**확인 범위와 한계**: 2026-09-22에 위 세 파일을 읽어 작성했다. **렌더링된 화면을 직접 보지 않았다.** 아래 ‘관찰된 구현’은 전부 코드에서 읽은 값이며, 실제 표시 결과·대비 측정값·기기별 동작은 확인하지 않았다.

토큰 값 전체를 이 문서에 복제하지 않는다. 값은 [site/style.css](../site/style.css)의 `:root`에 있고, 여기에는 사용 원칙만 남긴다.

## 관찰된 구현

- **테마**: 라이트가 기본이고 `:root[data-theme="dark"]`와 `@media (prefers-color-scheme: dark)` 두 경로로 다크가 적용된다. 시스템 설정을 따르되 헤더의 토글로 덮어쓸 수 있고 선택은 `localStorage`에 저장된다. 깜빡임을 막으려고 `index.html` `<head>`의 인라인 스크립트가 스타일시트보다 먼저 `data-theme`을 세팅한다.
- **색**: 모든 색이 `:root`의 CSS 변수로만 정의되어 있고 컴포넌트에 하드코딩된 색이 없다. 역할별로 텍스트 4단계(`--fg`, `--fg-secondary`, `--fg-dim`, `--fg-faint`), 면 3단계(`--card`, `--surface`, `--surface-hover`), 선 3단계(`--line`, `--edge`, `--line-strong`), 강조(`--accent`, `--accent-deep`, `--accent-soft`), 경고(`--danger-*`)로 나뉜다. 라이트 팔레트의 각 값에는 계산한 대비비가 주석으로 붙어 있다.
- **타이포그래피**: 본문 16px/1.5, 본문 폭 `max-width: 672px`. 실제 사용된 `font-size`는 12·13·14·16·18·20px 여섯 개뿐으로 [SPEC.md](../SPEC.md) 6.6의 램프와 일치한다. 폰트는 시스템 스택(`Helvetica Neue` → `-apple-system` → `Apple SD Gothic Neo` → `Pretendard`)이며 웹폰트를 받지 않는다.
- **레이아웃**: 폰 우선 단일 컬럼. 헤더는 스크롤과 함께 올라가고(고정 아님) 목록이 본문 전체를 차지한다. `env(safe-area-inset-*)`를 상단 패딩과 하단 패딩에 반영한다.
- **컴포넌트**: 칩(`.chip-row button`), 목록 행(`.row` — 제목 `.t`, 설명 `.d`, 시각 `.when`, 소스 뱃지 `.badge`, 외부 링크 `.ext`), 날짜 헤더(`.day-head`), 배너 2종(`#banner` 전역 신선도, `#sourceBanner`), 빈 상태(`.empty`), 더 보기 버튼(`.more-btn`), 상태 줄(`.status`), 푸터(`.foot`).
- **상태 표현**: 버튼에 기본·`:hover`·`:active`·`.on`(선택됨)이 있고, 선택된 칩은 `::before` 점 하나를 추가로 그린다. 멈춘 소스의 칩은 `data-state="stalled"` 속성으로 경고색이 된다. 배너는 `.src-alert`(빨강)와 `.src-warn`(회색)으로 심각도를 구분한다 — 소스 1~2개의 단발 실패를 빨간불로 만들지 않는다는 [SPEC.md](../SPEC.md) 4.2 규칙이 색으로도 반영돼 있다.
- **모션**: 전환은 160ms에 `--ease-out`(`cubic-bezier(0.16, 1, 0.3, 1)`) 하나로 통일돼 있다. 눌림은 `translateY(1px)`로만 표현한다.
- **접근성 관련 구현**: `:focus-visible`에 `--accent-deep` 2px 아웃라인 + 2px 오프셋이 공통으로 걸려 있다. `@media (prefers-reduced-motion: reduce)`에서 전환을 0.01ms로 죽인다. 배너 2개에 `role="status"`, 검색 입력과 테마 토글에 `aria-label`이 있다. 브랜드 로고 이미지는 `alt=""`로 장식 처리했다.
- **반응형**: 분기점은 `max-width: 520px` 하나다. 그 아래에서 좌우 패딩이 14px→12px로 줄고, 터치 대상이 커진다(버튼·칩 34/30px → 36px, 외부 링크 버튼 36×36px, 행 최소 높이 68px).

## 합의된 디자인 기준

아래는 [SPEC.md](../SPEC.md) 6.6에 확정된 기준이다. 근거 작업은 커밋 `0f48528`(`site: raise light-mode legibility to measured contrast targets`)이다. v1 라이트 모드에서 배경과 카드의 명도차가 2%뿐이고 `--fg-faint`가 2.7:1이었던 문제를 계산으로 다시 정한 결과다.

- 시각적 방향과 레이아웃: 본문 16px/1.5, 본문 폭 672px, 글자 크기는 `12 / 13 / 14 / 16 / 18 / 20`만 사용하고 12px 미만을 만들지 않는다. 그림자의 흐림값은 거리의 2배로 고정하고 깊이 표현을 섞지 않는다.
- 색: 본문·라벨 대비 4.5:1 이상, 설명·메타는 7:1 목표, 포커스 링 같은 비텍스트는 3:1 이상. **흰 카드와 페이지 배경 양쪽 면에서** 만족해야 한다. 카드와 배경의 명도차는 7% 안에 둔다(현재 4.7%). 중성색은 HSB 채도 5% 미만의 쿨 계열만 쓰고 웜과 섞지 않는다(경고색은 의미색이라 예외). 순검정·순흰색은 본문에 쓰지 않는다.
- 경계: 컨테이너 경계선은 카드·배경 양쪽과 구분되는 `--edge`를, 카드 안쪽 구분선은 더 연한 `--line`을 쓴다. 굳은 경계를 두 겹으로 붙이지 않는다.
- 공통 컴포넌트와 상태: 색은 반드시 `:root`의 토큰을 거친다. 새 색을 하드코딩하지 않으며, 색을 만질 때는 위 대비 기준을 다시 계산한다.
- 기준 출처: [Anthony Hobday, *Visual design rules you can safely follow every time*](https://anthonyhobday.com/sideprojects/saferules/).

반응형과 접근성에 대해서는 SPEC에 명시된 합의 기준이 없다. 위 ‘관찰된 구현’의 값들(520px 분기점, 36px 터치 대상, 포커스 링 사양)은 현재 코드에서 읽은 것이지 확정된 규칙이 아니다. **코드에 있다는 이유만으로 규칙으로 확정하지 않는다.**

## 불일치와 미정 사항

- **반응형 기준이 미정이다.** 분기점 520px과 터치 대상 36px의 근거가 문서에 없다. 값 자체는 일관되게 적용돼 있다.
- **접근성 기준이 미정이다.** 포커스 링·`prefers-reduced-motion`·`role="status"`가 구현돼 있지만 어느 수준을 목표로 하는지(예: WCAG AA)가 정해져 있지 않다. 대비 목표만 SPEC 6.6에 있다.
- **다크 모드의 대비는 미확인이다.** 라이트 팔레트에는 계산한 대비비가 값마다 주석으로 붙어 있으나 다크 팔레트에는 없다. SPEC 6.6도 "라이트 모드 기준"이라고 명시한다.
- **렌더링된 화면을 확인하지 않았다.** 이 문서의 관찰은 전부 코드 기준이다. 실제 표시·대비 측정·기기별 동작은 확인이 필요하다.
- **다크 팔레트에서 `--line`과 `--edge`가 같은 값(`#2d2d2d`)이다.** 라이트에서는 둘을 구분해 쓰는데(카드 안쪽 vs 컨테이너 경계) 다크에서는 구분이 사라진다. 의도된 것인지 확인되지 않았다.

## 디자인 확인 방법

변경 후 확인할 범위다. 실제 확인 결과와 미확인 범위는 개별 작업 문서에 남긴다.

- 화면: 기본 피드(항목 있음), 빈 상태(기간에 0건), 소스 필터로 0건, Show HN 칩 선택(점수 정렬·날짜 헤더 없음), 검색 결과, 전역 신선도 배너 노출, 소스 상태 줄 2종(`src-alert`·`src-warn`).
- 화면 크기: 520px 미만(폰)과 그 이상 두 가지. 본문 폭 672px 상한이 걸리는 넓은 화면도 함께 본다.
- 테마: 라이트·다크 각각, 그리고 시스템 설정과 토글이 어긋난 조합.
- 상태: 칩의 기본/선택/멈춤(`data-state="stalled"`), 행의 hover/active, 키보드 Tab 이동 시 포커스 링.
- 조작: 행 탭(원문 이동)과 `↗` 탭(외부 링크)이 겹치지 않는지, `남은 N건 보기` 이후 스크롤 위치 복원.
