# UI 디자인 기준

UI의 시각적 기준과 상호작용·반응형·접근성 기준을 다룬다. 시스템 구조는 [docs/architecture.md](architecture.md), 기술 스택·구현 도구 설정·검증 명령은 [docs/specs.md](specs.md)에서 관리한다.

합의된 디자인 기준의 정본은 [SPEC.md](../SPEC.md) 6.6이다. 여기서는 그 기준과 현재 코드에서 관찰한 구현을 연결하고, 확인하지 못한 것을 구분해 남긴다.

## 참고할 코드와 화면

- [site/style.css](../site/style.css) — 디자인 토큰(`:root`), 라이트/다크 팔레트, 컴포넌트 스타일 전부.
- [site/index.html](../site/index.html) — 화면 골격. 헤더(브랜드·테마 토글·배너 2종·검색·칩 3줄·건수 줄), 목록, 푸터.
- [site/app.js](../site/app.js) — 렌더 로직. 어떤 상태에서 어떤 컴포넌트가 나오는지는 여기서 정해진다.
- [SPEC.md](../SPEC.md) 6절 — 화면 동작과 색·글자 기준의 정본.
- [site/icon.svg](../site/icon.svg) — 브랜드 마크의 원본. 홈 화면 아이콘·스플래시·OG 이미지는 여기서 파생된다(아래 ‘브랜드 에셋’).
- 배포된 화면: `https://gonasooc.github.io/idea-radar/` ([site/index.html](../site/index.html)의 `og:url`).

**확인 범위와 한계**: 2026-09-22에 위 세 파일을 읽어 작성했고, 2026-09-28에 헤드리스 Chrome 154로 렌더링을 직접 보고 측정해 갱신했다(390×844 @2x와 1280×900, 라이트·다크, 상단 안전 영역 47px 에뮬레이션 포함 — 방법과 결과는 [docs/work/W-002-main-ui-usability.md](work/W-002-main-ui-usability.md)). **실기기(iPhone 홈 화면 앱)는 확인하지 않았다.**

토큰 값 전체를 이 문서에 복제하지 않는다. 값은 [site/style.css](../site/style.css)의 `:root`에 있고, 여기에는 사용 원칙만 남긴다.

## 관찰된 구현

- **테마**: 라이트가 기본이고 `:root[data-theme="dark"]`와 `@media (prefers-color-scheme: dark)` 두 경로로 다크가 적용된다. 두 경로의 다크 값은 같은 값을 복제한 것이라 한쪽만 고치면 토글 다크와 시스템 다크가 달라진다. 시스템 설정을 따르되 헤더의 토글로 덮어쓸 수 있고 선택은 `localStorage`에 저장된다. 토글로 시스템과 같은 쪽으로 돌아오면 저장을 지워 다시 시스템 설정을 따른다(2026-09-28부터 — 전에는 한 번 누르면 다시는 시스템 전환을 따르지 않았다). 깜빡임을 막으려고 `index.html` `<head>`의 인라인 스크립트가 스타일시트보다 먼저 `data-theme`을 세팅한다.
- **색**: 글자·면·선 색은 모두 `:root`의 CSS 변수를 거친다. 2026-09-28에 `.more-btn`의 하드코딩 `#171717`을 `--on-accent` 토큰으로 옮겼다. 그림자 세 곳(버튼·검색창의 `0 1px 2px`, 로고)만 rgba 리터럴이다. 역할별로 텍스트 4단계(`--fg`, `--fg-secondary`, `--fg-dim`, `--fg-faint`), 면 3단계(`--card`, `--surface`, `--surface-hover`), 선 3단계(`--line`, `--edge`, `--line-strong`), 강조(`--accent`, `--accent-deep`, `--accent-soft`, `--on-accent`), 경고(`--danger-*`)로 나뉜다. 라이트 팔레트는 값마다, 다크 팔레트는 블록 머리에 계산한 대비비가 주석으로 붙어 있다.
- **타이포그래피**: 본문 16px/1.5, 본문 폭 `max-width: 672px`. 실제 사용된 `font-size`는 12·13·14·16·18·20px 여섯 개뿐으로 [SPEC.md](../SPEC.md) 6.6의 램프와 일치한다. 폰트는 시스템 스택(`Helvetica Neue` → `-apple-system` → `Apple SD Gothic Neo` → `Pretendard`)이며 웹폰트를 받지 않는다. `body`에 `word-break: keep-all`을 걸어 한국어는 띄어쓰기에서만 줄을 바꾼다 — 전에는 줄바꿈의 약 21%가 "서비/스"처럼 단어를 갈랐다. 띄어쓰기 없는 긴 문자열은 제목·설명의 `overflow-wrap: anywhere`가 받는다.
- **레이아웃**: 폰 우선 단일 컬럼. 헤더는 스크롤과 함께 올라가고(고정 아님) 목록이 본문 전체를 차지한다. `env(safe-area-inset-*)`를 상단 패딩과 하단 패딩에 반영한다. 홈 화면 앱(`black-translucent`)을 위해 날짜 헤더는 `top: env(safe-area-inset-top)`에 붙고, `body::before`가 상태 표시줄 높이만큼 `--bg` 띠를 고정으로 깐다. 브라우저 탭에서는 둘 다 0이다.
- **컴포넌트**: 칩(`.chip-row button`), 목록 행(`.row` — 제목 `.t`, 설명 `.d`, 시각 `.when`, 소스 뱃지 `.badge`, 외부 링크 `.ext`), 날짜 헤더(`.day-head`, `h2`), 수집 실행 경계(`.run-head`, `h3` — 12px `--fg-faint`, 붙지 않음), 검색어 강조(`mark` — `--accent-soft` 면에 `--fg` 글자), 배너(`#banner` 전역 신선도·연결 문제, `#sourceBanner`), 빈 상태(`.empty` — 첫 줄 상태, 둘째 줄부터 13px `--fg-faint` 근거), 다시 시도 버튼(`.retry-btn`), 더 보기 버튼(`.more-btn`), 상태 줄(`.status`), 푸터(`.foot`).
- **상태 표현**: 버튼에 기본·`:hover`·`:active`·`.on`(선택됨)이 있고, 선택된 칩은 `::before` 점 하나를 추가로 그린다. 멈춘 소스의 칩은 `data-state="stalled"` 속성으로 경고색이 된다. 배너는 `.src-alert`(빨강)와 `.src-warn`(회색)으로 심각도를 구분하고, 소스가 여럿이면 한 줄에 하나씩 쓴다 — 소스 1~2개의 단발 실패를 빨간불로 만들지 않는다는 [SPEC.md](../SPEC.md) 4.2 규칙이 색으로도 반영돼 있다. manifest를 받지 못한 경우(`#banner.net-warn`)도 수집이 아니라 연결 문제라 같은 회색을 쓴다.
- **모션**: 전환은 160ms에 `--ease-out`(`cubic-bezier(0.16, 1, 0.3, 1)`) 하나로 통일돼 있다. 눌림은 `translateY(1px)`로만 표현한다. iOS Safari는 `touchstart` 리스너가 없으면 탭에 `:active`를 걸지 않아서, `app.js`가 아무 일도 하지 않는 passive 리스너를 하나 둔다(실기기 미확인).
- **접근성 관련 구현**: `:focus-visible`에 `--accent-deep` 2px 아웃라인 + 2px 오프셋이 공통으로 걸려 있고, `↗`는 세로로 긴 탭 영역 대신 안쪽 상자에 링을 그린다. `@media (prefers-reduced-motion: reduce)`에서 전환을 0.01ms로 죽인다. 배너 2개에 `role="status"`, 검색 입력과 테마 토글에 `aria-label`이 있다. 검색 입력은 `<form role="search">` 안에 있고, 칩 줄 셋은 `role="group"`과 이름(소스·기간·검색 기간)을 갖는다. 날짜 헤더와 실행 경계는 제목 요소(`h2`·`h3`)다. `↗` 링크의 접근 가능한 이름은 `{제목} 제품 사이트 열기`다(전에는 글리프 `↗`뿐이었다). 브랜드 로고 이미지는 `alt=""`로 장식 처리했다.
- **반응형**: 분기점은 `max-width: 520px` 하나다. 그 아래에서 좌우 패딩이 14px→12px로 줄고, 터치 대상이 커진다(버튼·칩 34/30px → 36px, 외부 링크 상자 36×36px, 행 최소 높이 68px). `↗`의 탭 영역은 행 오른쪽 여백 전체(52px, 폰 50px × 행 높이)이고 보이는 상자는 그 가운데 있다 — 전에는 행 높이 98px 중 36px만 `↗`이고 위아래 62px은 원문 링크였다.
- **브랜드 에셋**: `apple-touch-icon.png`(180)·`icon-192.png`·`icon-512.png`는 `icon.svg`의 도형을 `#1c1c1c` 정사각형에 꽉 채워(모서리는 OS가 깎는다), `icon-512-maskable.png`는 도형을 90%로 줄여 안전 영역(지름 80%) 안에 넣는다. iOS 스플래시 10종은 `#171717` 바탕 가운데 112px 타일과 그 아래 17px/600 `#a1a1a1` 워드마크, OG(1200×630)는 `#171717` 바탕 왼쪽 230px 타일과 96px 제목·34px 한 줄 소개다. `site.webmanifest`의 `theme_color`·`background_color`는 `#171717`이다. **`icon.svg`를 바꾸면 이 15개 파일을 같은 구성으로 다시 뽑는다** — 2026-07-29 재디자인(`ab4308b`) 때 `icon.svg`만 바뀌고 이 파일들은 v1 색(남색·파랑·주황, `#0e1420`)으로 두 달간 남아 있었다.

## 합의된 디자인 기준

아래는 [SPEC.md](../SPEC.md) 6.6에 확정된 기준이다. 근거 작업은 커밋 `0f48528`(`site: raise light-mode legibility to measured contrast targets`)이다. v1 라이트 모드에서 배경과 카드의 명도차가 2%뿐이고 `--fg-faint`가 2.7:1이었던 문제를 계산으로 다시 정한 결과다.

- 시각적 방향과 레이아웃: 본문 16px/1.5, 본문 폭 672px, 글자 크기는 `12 / 13 / 14 / 16 / 18 / 20`만 사용하고 12px 미만을 만들지 않는다. 그림자의 흐림값은 거리의 2배로 고정하고 깊이 표현을 섞지 않는다.
- 색: 본문·라벨 대비 4.5:1 이상, 설명·메타는 7:1 목표, 포커스 링 같은 비텍스트는 3:1 이상. **흰 카드와 페이지 배경 양쪽 면에서** 만족해야 한다. 카드와 배경의 명도차는 7% 안에 둔다(현재 4.7%). 중성색은 HSB 채도 5% 미만의 쿨 계열만 쓰고 웜과 섞지 않는다(경고색은 의미색이라 예외). 순검정·순흰색은 본문에 쓰지 않는다.
- 경계: 컨테이너 경계선은 카드·배경 양쪽과 구분되는 `--edge`를, 카드 안쪽 구분선은 더 연한 `--line`을 쓴다. 굳은 경계를 두 겹으로 붙이지 않는다.
- 공통 컴포넌트와 상태: 색은 반드시 `:root`의 토큰을 거친다. 새 색을 하드코딩하지 않으며, 색을 만질 때는 위 대비 기준을 다시 계산한다.
- 기준 출처: [Anthony Hobday, *Visual design rules you can safely follow every time*](https://anthonyhobday.com/sideprojects/saferules/).

반응형과 접근성에 대해서는 SPEC에 명시된 합의 기준이 없다. 위 ‘관찰된 구현’의 값들(520px 분기점, 36px 터치 대상, 포커스 링 사양)은 현재 코드에서 읽은 것이지 확정된 규칙이 아니다. **코드에 있다는 이유만으로 규칙으로 확정하지 않는다.**

## 불일치와 미정 사항

- **반응형 기준이 미정이다.** 분기점 520px과 터치 대상 36px의 근거가 문서에 없다. 값 자체는 일관되게 적용돼 있다.
- **접근성 기준이 미정이다.** 포커스 링·`prefers-reduced-motion`·`role="status"`가 구현돼 있지만 어느 수준을 목표로 하는지(예: WCAG AA)가 정해져 있지 않다. 대비 목표만 SPEC 6.6에 있다.
- **다크 모드 대비는 2026-09-28에 계산했다 — 다만 목표는 합의되지 않았다.** SPEC 6.6은 "라이트 모드 기준"이다. 라이트와 같은 목표로 재 보니 `--fg-faint`(`#737373`)가 카드 3.59 / 배경 3.78 / 행 hover 위 3.23:1로 날짜·점수·푸터·`↗`·검색 placeholder가 본문 기준 4.5:1에 못 미쳐 `#8c8c8c`(5.07 / 5.33 / 4.56)로 올렸다. 이건 WCAG AA 텍스트 기준으로도 미달이던 값이다. `--fg-dim`은 6.60 / 6.94:1로 라이트(7.03 / 6.29)처럼 7:1 목표에 조금 못 미치지만 그대로 뒀다. 다크에도 SPEC 6.6과 같은 목표를 적용할지는 **제안이지 확정이 아니다.**
- **다크 `--edge`를 `--line`과 다른 값으로 나눴다(2026-09-28).** 전에는 둘 다 `#2d2d2d`라 컨테이너 경계와 카드 안쪽 구분선이 같았고, 카드는 배경과 1.05:1이라 경계선이 거의 유일한 면 구분이었다. 같은 값이었던 이유는 `--edge`를 신설한 커밋 `0f48528`의 본문에 있다 — "다크 값은 기존 --line과 동일해 다크 모드 색은 불변". 라이트 가독성 작업에서 다크를 바꾸지 않으려던 범위 결정이지, 둘을 같게 두는 규칙은 아니었다. SPEC 6.6의 경계 원칙(경계는 카드·배경 양쪽과 구분, 안쪽 구분선은 더 연하게)을 다크에도 적용해 `--edge`를 `#3a3a3a`(카드 1.50 / 배경 1.58, 라이트 1.74 / 1.55와 같은 급)로 올렸다. 되돌리려면 두 다크 블록의 값을 `#2d2d2d`로 바꾼다.
- **렌더링은 헤드리스 Chrome으로만 봤다.** iOS Safari·홈 화면 앱에서의 표시, `:active` 탭 피드백, `U+FE0E`를 붙인 `☀`·`↗`가 이모지로 바뀌지 않는지는 실기기 확인이 필요하다.
- **홈 화면 앱의 상태 표시줄 글자색이 라이트 테마에서 안 보일 수 있다(미확인).** `apple-mobile-web-app-status-bar-style`이 `black-translucent`라 상태 표시줄 글자가 흰색인데, 라이트 테마의 상단은 `#eff3f3`이다. 2026-09-28에 추가한 상단 `--bg` 띠는 이 조건을 바꾸지 않는다(라이트에서는 원래도 같은 색 위였다). 실기기에서 확인한 뒤 `default`로 바꿀지 정한다 — 바꾸면 화면이 상태 표시줄 아래에서 시작하므로 안전 영역 처리도 함께 바뀐다.

## 디자인 확인 방법

변경 후 확인할 범위다. 실제 확인 결과와 미확인 범위는 개별 작업 문서에 남긴다.

- 화면: 기본 피드(항목 있음 — 날짜 헤더의 오늘/어제, 실행 경계), 빈 상태(기간에 0건), 소스 필터로 0건, Show HN 칩 선택(점수 정렬·날짜 헤더 없음), 검색 결과(여러 단어, 강조, 클램프를 펼친 행, 월 경계 구분선), 검색 0건(Show HN 안내), 전역 신선도 배너 노출, 연결 문제 배너(`net-warn`), 소스 상태 줄 2종(`src-alert`·`src-warn`), 캐시 없는 첫 방문의 로딩·실패.
- 화면 크기: 520px 미만(폰)과 그 이상 두 가지. 본문 폭 672px 상한이 걸리는 넓은 화면도 함께 본다. 상단 안전 영역이 있는 경우(홈 화면 앱)의 sticky 날짜 헤더.
- 테마: 라이트·다크 각각, 그리고 시스템 설정과 토글이 어긋난 조합. 토글을 두 번 눌러 시스템 추종으로 돌아오는지.
- 상태: 칩의 기본/선택/멈춤(`data-state="stalled"`), 행의 hover/active, `↗` 여백 hover(행이 아니라 상자만 강조), 키보드 Tab 이동 시 포커스 링.
- 조작: 행 탭(원문 이동)과 `↗` 탭(외부 링크)이 겹치지 않는지, 검색에서 Enter, `남은 N건 보기` 이후 스크롤 위치 복원, 새 데이터가 온 뒤 읽던 행이 같은 자리인지, 오래된 캐시로 연 첫 화면에 빨간 배너가 번쩍이지 않는지.
